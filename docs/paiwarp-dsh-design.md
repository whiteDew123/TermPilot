## 从一句话到教程素材

你在桌面聊天框说「帮我重新跑一下第一章里的 Case」。Harness 读取当前工作区的教程目录，定位第一章，找出实际操作、预期结果和配图位置。它调用 paiwarp-dsh 在这台 Mac 上开一个专用终端，逐步输入教程里的命令，等待现场反馈，核对结果，截取关键画面，把录屏保存到 Case 目录，再原位替换教程中与这些步骤对应的已有截图。正常跑完只需要最初那句话。右侧面板用来看现场，需要时可以接管或停止。

如果一章有多个 Case，就逐个列出和复跑，共用的构建步骤可复用一次。教程正文是测试材料；代码讲解、示意输出和首次配置说明要分别识别。例如本机已有项目配置时，跳过「复制示例配置并填 Key」，保留现有配置。旧教程无需先改写成脚本。命令、工作目录、输入对象、检查条件和拍摄点可从正文整理成一份步骤表；只有无法辨认且会影响执行的地方才交给作者补充。

## 什么叫在本机真实运行

伪终端（PTY）是操作系统给交互程序用的终端设备。它让 Java 可以逐键读取输入、识别窗口大小和处理 Ctrl+C。它与沙箱是两个独立问题：同一个程序既可以在受限环境里的 PTY 运行，也可以在本机用户权限的 PTY 运行。

建议把「在本机运行教程 Case」作为桌面插件明确提供、由用户启用的能力。运行前校验当前桌面连接的是本机执行服务。由本机侧按登录用户身份启动专属终端，从选定工作区读取配置，在同一进程中保持多轮交互。记录工作目录、运行器身份、shell 与 Java 进程、工具实际路径，用本次所需的文件读写、Maven 依赖访问和模型调用验证环境符合 Case 要求。终端里执行的是用户真实可用的工具链，素材目录位于用户指定的本机仓库。

Harness 负责理解教程、组织步骤和判断现场结果。插件的本机运行服务负责按键、读屏、捕获画面、核对进程以及写入素材。选择这项能力时说明它可以用本机用户权限运行该 Case，同一轮自动执行获准的步骤；每个测试会话只能操作自己创建的终端。普通聊天工具继续使用其原有策略。若桌面部署或系统策略禁止本机执行，任务直接显示受阻的步骤；沙箱中的结果不能标记为本机实测。首轮技术验证优先测桌面插件能否在实际部署中按这一方式启动 Java、访问已有 Maven 缓存和本机配置、成功调用内层模型，并将文件写入指定目录。

官方右侧用户终端以执行环境的系统用户权限启动，Agent 的持久终端后端另行处理会话沙箱策略。官方提供了创建终端进程、写入按键、调整窗口和等待退出等接口。PaiWarp 的新增工作包括授权的本机 Case 执行、教程步骤编排、实况采集和素材写回。这些能力需要在桌面 App 集成验证。[官方用户终端](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/api/terminal-controller/README.zh.md) · [官方 Agent 终端后端](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/terminal/terminal-bash/src/index.ts) · [终端进程接口](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/subprocess/subprocess/src/types.ts)

## 画面、录屏和教程写回

- 同一终端的输出、光标和窗口尺寸驱动一个持续渲染的终端视图。截图取该视图此刻的实际画面；录像按时间连续采集该视图的画面，输出 MP4。原始文字日志另外保留，用来定位工具错误。采集范围是 Case 终端，画面中保留实际提示词、交互确认和程序输出。
- 截图跟着事件走。例如看见新的输入提示、文件修改结束、验证命令返回后拍摄。每张图关联本次运行、步骤和时间；核验后再选用。超时、黑帧、输出截断或录制异常要标明。前台权限确认由用户决定，等待期间显示原画面。
- 原始实测材料保存在对应 Case 目录。建议每次使用独立的 runs/<运行标识>/ 子目录，里面保存选中截图、录屏和简短运行记录。已有固定素材目录的教程沿用原约定。重跑后先验证新文件，再逐张匹配本次成功步骤对应的已有截图。没有对应截图、位置有歧义或实测结果与原文不符时，只保存素材并在运行报告中说明。
- **教程只允许原位替换对应的已有截图。** 如果该位置独用一份本地图片，可沿用原路径替换图片文件。需要换地址时，只改该图片标记中的地址，保留替代文字、图注和标题属性。当前 TermPilot 文章使用 CDN（存放公开配图的服务）链接，新截图上传且验证可访问后才替换对应地址。录屏和日志只保存在 Case 目录。
- **写回验收。** 根据指定截图的地址区间生成候选修改，核对区间之外的原始字节完全一致，包括正文、代码、空白、换行和其他链接。原路径复用时，教程文件应为零差异。若有额外差异就放弃写入；若作者在运行期间编辑了教程，则基于最新文件重新定位和核验。
- 可重复运行需要稳定的起始材料。若前一轮已把 Hello World 改成 Hello TermPilot，本轮从该 Case 的起始文件再跑；检查本次真实改动和输出，保留作者的业务代码与旧素材。内层 Agent 的话术、耗时、调用次数可以变化，验收看教程声称的行为和结果。

## 桌面界面

插件管理页沿用「插件 → 添加插件 → 本地目录」安装流程，显示名 PaiWarp，说明为「在本机复跑教程案例，保存录屏并原位替换教程截图」。[官方桌面插件管理](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/client/ui-plugin-manager/README.zh.md)

聊天开始后自动展开右侧面板。顶栏显示「第一章 · 修改并运行 Hello.java」「本机 Mac」及具体工作目录。主区域显示实时终端；下方一行说明目前在做什么，例如「已验证文件修改，正在等待编译输出」。截图成功时出现缩略图，录制中显示时长。完成后切到素材页，可逐张点开截图、播放视频、定位到教程中已经替换的截图。手工接管和停止作为次要控制，停止时先封存已经录到的画面，再清理本次进程。

## 审查通过后的第一道交付标准

在桌面 App 中只发一句复跑请求。从创建本机终端到两个真实 TermPilot 提问，再到原位换图和录屏归档，全链路走通。重新打开教程确认对应截图可见，在 Case 目录播放录屏，并验证教程差异只有指定截图地址；再跑一遍，检验起始材料能复原，且失败时旧素材仍可用。首版已通过这条桌面验收，输出、退出码、录屏时长和图片地址见[实测结果](../cases/chapter-01/runs/2026-11-10T05-33-14-600Z-f196f7a3/result.json)。
