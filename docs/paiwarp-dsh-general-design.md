# PaiWarp 通用插件设计

2026-11-11。本文是待实现的通用版设计，不表示现有两个插件已经具备这些能力。现有第一章、第二章插件和实测材料继续保留；正式教程正文不在本次修改范围内。

## 现有版本的边界

当前实现验证了真实终端、Agent 输入、截图、录屏和结果核对这条流程，但只覆盖两个指定案例。

| 当前代码 | 具体限制 |
| --- | --- |
| `plugins/paiwarp-dsh/host.js` | 工具入口叫 `paiwarp_run_chapter_one`；工作区必须等于插件目录的上两级目录；输入必须等于运行器给定的 `expected`。 |
| `plugins/paiwarp-dsh/chapter.py` | 写死第一章文章、两条提问、三个图片位置；上传依赖 `~/.codex/skills` 中的脚本和特定图床。 |
| `plugins/paiwarp-creator/host.js` | 工具入口叫 `paiwarp_creator_run_chapter_two`；工作区也绑定插件所在的 TermPilot 仓库；输入同样受预设步骤约束。 |
| `plugins/paiwarp-creator/creator_runner.py` | 写死第二章构建和运行流程，依赖专门的章节检查程序。 |
| `plugins/paiwarp-creator/package.json` | 标有 `private: true`，目前按本地目录安装，不是准备好发布的公共包。 |

因此，当前版本不能直接声称支持任意章节、任意项目。仅修改提示词或加一个 `chapter` 参数不足以解决问题。

## 产品目标

`paiwarp-dsh` 是 DeepSeek Harness 桌面端的通用终端操作与实测取证插件。Case 指一段有输入、操作步骤和预期结果的测试案例。TermPilot 是首个示例项目，不是插件的运行前提。

用户选中自己的项目，对 Harness 说：

> 按 docs/tutorial.md 的“跑起来看看”测试当前项目。用 PaiWarp 打开终端，逐步执行，验证结果，保存关键截图和录屏。现有教程只替换对应图片，其他内容不变。

Harness 阅读材料，分清命令、交互输入、示例输出和首次配置说明，再调用插件。遇到没见过的章节，可以根据实时输出调整操作。新章节不应要求修改插件源码或重新打包。

通用指能够操作不同终端程序，不代表自动保证每种程序或每篇教程都能通过。第三方登录、设备、服务和系统权限可能仍需要用户参与；缺少证据应报告未验证。

## 三部分职责

### 1. 插件管理真实终端

伪终端（PTY）是操作系统提供的交互终端设备，让命令行程序接收按键、感知窗口大小和保留多轮状态。插件在 Harness 授权的本机执行环境中创建它，管理进程、输入、输出和素材。

插件不硬编码 `mvn`、Java、TermPilot、章节编号、教程路径、项目目录或模型供应商。工作目录取当前 Harness 工作区；插件可以装在另一个目录。相对路径必须核实归属，终端只能由创建它的会话操作。

PTY 与沙箱是两个不同概念。通用版必须沿用 Harness 的权限检查，不能承诺绕过宿主或操作系统限制。报告记录实际工作目录、进程和执行环境，明确哪些程序真实运行了。

### 2. Harness 决定操作

Harness 根据用户请求和现场输出决定下一条输入、何时等待、何时截图、如何验证。默认不由运行器给出唯一允许输入的下一句话。

输入仍绑定会话、终端编号和操作序号，避免重复发送或操作别人的终端。序号用于防止误操作，不用于限制任务内容。终端输出作为不可信数据处理，不可自行扩张用户授权范围。

### 3. 示例描述具体案例

第一章、第二章移到 `examples/termpilot/`，保存教程定位、准备材料、预期结果、拍摄点和必要的 TermPilot 检查方法。另带一个不使用模型密钥的普通命令行示例。

用户第一次只给 Markdown 也能运行，不强制先编写案例配置。需要稳定复跑时，可以把核实后的步骤保存为案例文件；文件有格式版本，命令、按键、等待条件和检查项均可更改。TermPilot 的会话记录解析属于可选检查组件，不能成为通用终端的依赖。

## 提供给 Agent 的操作

下列是拟定接口，需要实现时对照官方插件接口核实注册和返回格式。

| 操作 | 用途与约束 |
| --- | --- |
| `paiwarp_open` | 在当前工作区创建终端，返回终端编号、工作目录、画面尺寸和运行状态。可选择是否从打开时录制。 |
| `paiwarp_read` | 返回当前可见屏幕和带游标的增量输出，说明是否截断。保留颜色控制后的真实显示内容。 |
| `paiwarp_input` | 明确区分输入文本、粘贴多行和发送按键；`Enter`、`Ctrl+C`、`Tab`、`Shift+Tab`、方向键与普通字母不能混淆。一次操作一个终端。 |
| `paiwarp_wait` | 有时限地等待新输出、指定条件或进程退出；超时返回现场，不能默认成功。 |
| `paiwarp_capture` | 保存当前终端真实画面，返回图片路径、对应输出位置和时间。 |
| `paiwarp_record` | 开始或停止终端画面录制，正常封存后返回视频路径。 |
| `paiwarp_close` | 关闭自己创建的终端及子进程，保存已有素材和退出状态；用户停止、取消、插件卸载时也要执行清理。 |

验证不能只做“包含某个词”：终端回显了命令，不代表命令执行成功；Agent 说“完成”，不代表磁盘文件符合要求。可结合退出码、文件内容、程序输出和可选的执行记录，逐项保存证据。通用交互程序无法可靠取得内部命令退出码时标为未知，不能拿终端 shell 的退出码代替。

## 桌面界面

右侧面板分为“终端”和“素材”两页。

- 顶部显示项目、当前终端、工作目录、运行状态和录制时长；有多个终端时可切换。
- 终端页显示同一 PTY 的实时画面，下方显示当前操作；提供暂停自动输入、接管、恢复、停止。接管期间拒绝 Agent 写入，避免两边抢键盘。
- 素材页列出截图、视频和检查结果，点击可以预览，失败步骤保留对应画面。
- 通用设置只放运行目录、shell、窗口尺寸、录制开关、等待上限等；教程路径和截图数量属于当前任务。

第一版无需复刻 Warp 的全部功能，先把 Agent 操作、用户观察与接管、实测证据连起来。

## 素材和只换图

默认保存到工作区 `.paiwarp/runs/<运行编号>/`，包含输入事件、输出记录、截图、视频和逐项检查报告。日志不记录环境变量值，凭据不放到工具参数、命令或截图里。默认不上传任何素材，原始终端日志也不自动作为开源示例打包。

更新教程是独立、显式请求的动作。通用插件先生成图片对应表，明确源文件、原图片地址和新图片路径；只在用户已经要求换图时应用。保留原始文件校验值，只替换对应图片地址的字节区间，写入前再检查文件未被其他人修改。保留替代文字、标题、正文、代码、空格和换行。位置不唯一、截图未通过核对或文件发生并发编辑时保留素材并报告，不猜测替换。

站点副本由使用者提供路径，分别检查每个文件；不内置固定站点路径。图床上传作为可选接入，使用者自行配置；本地图片流程不能依赖 Codex、私人脚本或图床账号。开源演示默认生成独立教程副本。

## 开源交付要求

- 对外保留一个主包 `paiwarp-dsh`。创造版留作历史制作案例，不把“第一章版、第二章版、第三章版”继续扩展成产品系列。
- 插件目录能够单独复制或克隆安装；包中包含运行所需文件和锁定依赖，安装后检查 Python、终端渲染与录像依赖，缺什么给出明确提示。
- 第一版以实际验证的 macOS 环境为准。Linux 和 Windows 必须分别验收；现有 Python `pty` 实现不意味着已经支持 Windows。
- 提供安装、卸载、权限说明、接口说明、案例格式、故障排查和贡献说明。仓库开源许可证及所复用代码的授权需要明确，再决定发布许可；当前设计不代替授权声明。
- 发布包排除运行日志、截图原始记录、`.env`、密钥、缓存和个人绝对路径；安装测试要从实际打包产物执行。
- 所有生成和运行步骤无需 Codex；公开创建提示词也不要求访问本机现有 PaiWarp 仓库来“复用参考实现”。

## 验收门槛

1. 从独立插件目录安装，在与插件无目录关联的新工作区，用普通 shell 和交互程序验证输入、回车、多行、特殊键、读屏、退出码及真实文件结果。
2. 原第一章、第二章作为示例通过，输入和判断都能在调用记录中核对。
3. 选取此前未接入的一章，只提供教程和当前项目，不修改核心代码，完成真实运行与证据收集。若该章依赖未配置，明确受阻处，不能算通过。
4. 再验证一个不使用 TermPilot 的小项目，证明没有隐藏的 jar、Maven、DeepSeek 密钥或 TermPilot 会话记录依赖。
5. 验证取消、超时、手工接管、权限变更、重复输入和多会话隔离；结束后本次终端和录像浏览器没有残留。
6. 逐帧可解码的视频、可打开的截图和检查报告都来自本次运行。教程及其副本只发生指定图片地址变化。

只有以上验收完成，才能称为可复用通用版。两章历史实测通过不能替代这些验证。
